# Task Calendar - плагин Obsidian

Календарь задач внутри Obsidian: сетка месяца с отметками по дням и список задач
выбранного дня. Живёт прямо в хранилище - `<vault>/.obsidian/plugins/task-calendar`.

**Инлайн-формат с 30.10.2026.** Задача - одна строка с чекбоксом и параметрами
`- [ ] Текст 📅 ... 🔁 ... ✅ ...`, подзадачи с отступом под ней. Блочный формат
3.0 (параметры отдельными строками `- 📅 ...`, тело с отступом под ними) больше
не читается: миграции нет, старые задачи переписываются руками. Пункт без галочки
задачей не бывает, поэтому старые блоки не подхватываются даже наполовину. До 3.0
задача была заметкой со свойствами в YAML - этот код тоже удалён.

## Стек

| Что | Чем |
|---|---|
| UI | Vue 3.5, `<script setup lang="ts">`, два компонента |
| Сборка | esbuild + esbuild-plugin-vue3, бандл в `main.js` (CJS) |
| Тесты | vitest 2 + jsdom + @vue/test-utils |
| Типы | TypeScript 4.7, `tsc -noEmit` |

**Node 18.** Из-за него vite остаётся на 5, а vitest на 2: выше требуют Node 20+.
Установка новых пакетов - с `--legacy-peer-deps`.

**minAppVersion 1.6.0.** Запись идёт через `vault.process` - он появился в
Obsidian 1.6.

## Команды

```bash
npm test           # 312 тестов, ~1.3 с
npm run test:watch
npm run typecheck  # tsc -noEmit
npm run build      # typecheck + прод-сборка в dist/
npm run dev        # esbuild в watch, пересобирает main.js на месте
```

Скрипты зовут бинарники через `./node_modules/.bin/` - на этом разделе (fuseblk)
npm не кладёт их в PATH, голое `vitest` не находится.

**`cannot execute binary file` на `npm test`** - шимы в `node_modules/.bin`
легли NTFS-ссылками (`IntxLNK` в начале файла) и не запускаются. Обход - звать
точки входа через node (замечено 14.10.2026):

```bash
node node_modules/vitest/vitest.mjs run
node node_modules/typescript/bin/tsc -noEmit -skipLibCheck
node esbuild.config.mjs production
```

**Чтобы правки увидел Obsidian**, нужен `npm run dev` (или `build` + копирование
`dist/main.js` в корень): Obsidian грузит собранный `main.js`, а не исходники.

**`@types/node` держим на 16.** TypeScript 4.7 не разбирает `.d.ts` новых версий
и сыплет синтаксическими ошибками в `node_modules/@types/node/*` - `skipLibCheck`
от синтаксических не спасает, и `typecheck` с `build` встают целиком. Поднимать
типы node можно только вместе с TypeScript.

**Установка - с `--legacy-peer-deps`**, иначе `npm install` упирается в конфликт
peer-зависимостей vite и vitest. Обратная сторона флага: npm перестаёт сам
доставлять peer-пакеты и **вычищает** уже поставленные. Так однажды пропал eslint,
которого не было в `package.json` - теперь он там объявлен явно. Если после
установки что-то из инструментов исчезло, смотреть надо сюда.

## Формат задачи

Задача - **строка задачи**: пункт списка с чекбоксом и параметрами-эмодзи, плюс
подзадачи с отступом под ней. Строка задачи и подзадачи вместе - **блок**. В одном
файле блоков может быть много: новые задачи складываются в годовые файлы
`YYYY.md`, а цепочка повтора держит рядом свой актуальный блок и архив
выполненных.

```markdown

- [x] Купить молоко 📅 2026-08-21 🔁 Каждый день ✅ 2026-08-21
	- [x] Проверить срок

```

| Параметр | Код | Что значит | Обязателен |
|---|---|---|---|
| 📅 | `U+1F4C5` | день задачи в череде, точка отсчёта повтора | да |
| ↔️ | `U+2194 U+FE0F` | день показа, если экземпляр перенесли. С 30.10.2026 плагин его только читает, при переносе пишет новую 📅 | нет |
| 🔁 | `U+1F501` | повтор | нет |
| ✅ | `U+2705` | маркер факта выполнения | нет |

**📅 и ↔️ - разные вещи.** 📅 - место блока в череде: по нему считается повтор и по
нему день считается занятым. ↔️ - день, на котором блок показывается. Есть ↔️ -
календарь, точка, просрочка и группа дня считаются по ней (`showDate`), нет -
по 📅.

**Файл - авторитет.** Любой параметр можно выставить, изменить или удалить руками,
это синхронизируется и работает. Плагин ничего не нормализует и не переписывает по
своей инициативе: единственная автоматика, живущая в файле, - переключение
чекбокса.

Правила разбора (всё в [src/taskFormat.ts](../src/taskFormat.ts)):

- **Строка задачи - пункт списка нулевого уровня с галочкой** (`TASK_HEAD`) и хотя
  бы одним параметром. Пункт без галочки задачей не бывает, даже с эмодзи: так
  блоки старого формата (`- 📅 2026-08-21` отдельной строкой) не подхватываются
  наполовину, с пустым пунктом в карточке и ✅, дописанной в чужую строку.
- **Параметр - это пара «эмодзи + значение»** (`lineParams`). Эмодзи стоит в
  начале текста задачи или после пробела, приклеенный к слову - текст.
- **У 📅, ↔️ и ✅ значение - слово вида `YYYY-MM-DD`** сразу за эмодзи
  (`DATE_WORD`). Другое слово значением не считается, и эмодзи остаётся текстом:
  в `- [ ] ✅ Проверить отчёт 📅 ...` параметра ✅ нет. Иначе выполнение
  переписало бы «Проверить» датой. Что стоит за датой до следующего параметра
  (`#тег`, слова), остаётся текстом задачи.
- **У 🔁 значение - весь текст до следующего параметра, тега или конца строки**:
  повтор пишется словами, а `#` в его грамматике нет. Без остановки на теге
  `🔁 Каждый день #дом` не разобрался бы, и задача молча пропала бы с календаря.
- **Параметр повторился - в счёт идёт первый**, остальные остаются текстом.
- **Порядок параметров при чтении произвольный.** Новый параметр вписывается по
  канону 📅, ↔️, 🔁, ✅: перед первым, который должен идти позже, иначе за последним
  (`withParam`). Существующий заменяется на месте, остальной текст строки не
  трогается.
- **↔️ читается и без селектора** `U+FE0F` (`↔ 2026-08-25`), при записи селектор
  ставится всегда: без него в части тем стрелка рисуется текстом.
- **Мусор в ↔️ блок не ломает** - блок показывается по своей 📅. Это отличие от 🔁,
  где неразобранный текст делает блок невалидным: 📅 у блока есть всегда, а прятать
  задачу из-за кривой даты хуже, чем показать её на своём дне.
- **Дата - строго `YYYY-MM-DD`.** Вся арифметика на локальных календарных датах,
  `Date` в UTC не используется, время и таймзоны не хранятся. `21.08.2026` датой
  не считается, `2026-02-30` - параметр, но блок с такой 📅 невалиден.
- **Тело - строка задачи и строки с отступом под ней.** В карточку идут только
  списки: строка задачи без параметров, чекбоксы, маркированные и нумерованные
  пункты любой вложенности. Абзацы, заголовки, цитаты, таблицы и строки внутри
  блоков кода выбрасываются. Эмодзи в подзадачах параметрами не считаются: строки с
  отступом задачей не бывают, вложенные задачи не поддерживаются.
- **Отступы при чтении** - таб, 2 или 4 пробела, в одном файле вперемешку. Шаг в
  пробелах вычисляется по блоку: берётся самый маленький ненулевой пробельный
  отступ, остальные меряются им. **При записи** - табы, 1 таб на уровень.
- **Граница блока.** Каждая строка задачи открывает свой блок. **Пустые строки
  границей не являются** - блоки в файле идут подряд, без разделителей.
- **Непустая строка нулевого уровня, не строка задачи, блок закрывает** (правка от
  16.10.2026): заголовок, абзац, чужой пункт списка. Строки с отступом под ней -
  её подпункты, а не тело задачи выше. Раньше такая строка в блок не попадала, но
  и не закрывала его, и в заметке вида «задача с 📅, `# Заголовок`,
  `- [ ] Пункт` с подпунктами» подпункты уезжали в тело задачи - в карточку и в
  подсветку перехода.
- **Блок кода нулевого уровня - не задачи** (правка от 30.10.2026). Открывающая
  ограда (```` ``` ```` или `~~~`) закрывает задачу над ней, а всё до закрывающей
  ограды (тот же символ, не короче) ничьё: ни строки задач, ни тело. Без этого
  пример формата в заметке (`- [ ] Task 📅 ...` внутри ```` ``` ````) уходил в
  календарь, отметка писала повторы прямо в код, а новая задача дописывалась
  внутрь блока кода, если он стоял последним. Блок кода с отступом внутри задачи
  отдельно не отслеживается: его строки и так тело, их не показывает
  `renderLines`, а строка нулевого уровня кончает и пункт, и код в нём.
- **Идентификация.** Отдельного айди нет. Конкретный экземпляр адресуется парой
  «файл + порядковый номер блока»: `key` вида `/Папка/Имя.md#0`. Номер
  пересчитывается при каждой переиндексации.
- **Цепочка повтора** (правка от 15.10.2026) - блоки одного файла с одинаковым
  текстом задачи: первым пунктом тела без маркера, галочки и параметров
  (`chainKeyOf`, `Task.chain`). Своего айди у цепочки нет, а в общем файле рядом
  лежат чужие задачи. Повтор, отмеченный наперёд день и перенесённый экземпляр
  получают копию тела, поэтому текст задачи у них общий.

### Валидный блок

Блок попадает в карту и рисуется карточкой, только если выполнено **всё**:

1. есть 📅 с корректной датой;
2. в теле есть хотя бы один чекбокс - строка задачи с галочкой и есть он;
3. если есть 🔁, её текст разобрался по грамматике.

Иначе блок игнорируется **молча**: в карту не попадает, карточка не рисуется, файл
не правится, `Notice` не показывается. Это касается и задач с кривой датой, и задач
с нераспознанным повтором - соврать о дате хуже, чем не показать.

**Ни имя файла, ни папка на разбор не влияют:** сканируются все `.md`
хранилища, задачей файл делает валидный блок внутри. Папка из настроек - только
место, куда кладутся новые задачи (правка от 14.10.2026).

### Грамматика повтора

```
кажд<окончание> [<N>] <единица> [в <список>]
```

Регистр не важен, пробелы обрезаются, согласование числа и слова не проверяется -
«каждые 2 дня» и «каждый 2 день» одно и то же. Без числа N = 1.

| Единица | Формы |
|---|---|
| день | день, дня, дней, дни |
| неделя | неделя, неделю, недели, недель, неделе |
| месяц | месяц, месяца, месяцев, месяцы |
| год | год, года, году, годов, годы, лет |
| дни недели | понедельник, вторник, среда/среду, четверг, пятница/пятницу, суббота/субботу, воскресенье (плюс родительный и множественное) |
| месяцы | январь/января/январе и так же остальные одиннадцать |

**Оговорка `в <список>` уточняет только свою единицу:** дни недели - неделю,
месяцы - год. `Каждый месяц в Субботу`, `Каждый день в Субботу`,
`Каждую неделю в Марте` и `Каждый год в Марте, Субботу` не принимаются, и блок
становится невалидным.

Перечислять можно через запятую или «и»: `Каждую неделю в Понедельник, Среду`,
`Каждый год в Марте, Сентябре`.

Сверх спецификации парсер понимает то, что умел и раньше (решение от 22.08.2026 -
строже не делать, чтобы старые формулировки не роняли блок в невидимость):

- наречия `Ежедневно`, `Еженедельно`, `Ежемесячно`, `Ежегодно`;
- короткие формы `Каждую субботу` = `Каждую неделю в субботу`, `Каждый март` =
  `Каждый год в марте`;
- число с наращением: `каждый 2-й день`;
- лишние падежи в словах.

Расширять грамматику - только в `parseRepeat()`, остальной код о ней не знает.

### Расчёт следующей даты

База - **📅 выполненного блока**. Шаг применяется **ровно один раз**. Ни ✅, ни
сегодняшний день в расчёте не участвуют.

| Повтор | Правило |
|---|---|
| `день`, N | база + N дней |
| `неделя`, N, без дней | база + 7×N дней |
| `неделя`, N, дни D | ближайший день из D строго после базы внутри её же ISO-недели (Пн-Вс); такого нет - неделя базы + N недель, самый ранний день из D |
| `месяц`, N | база + N месяцев, число сохраняется, при переполнении зажимается до последнего дня месяца (31 -> 28/29/30) |
| `год`, N, без месяцев | база + N лет, 29 февраля -> 28 февраля |
| `год`, N, месяцы M | число месяца от базы; ближайший месяц из M строго после базы в том же году, иначе год базы + N и самый ранний месяц из M; число зажимается по длине месяца |

Зажим числа делает сам moment - `.add(n, 'month')` и `.month(m)` не переносят
дату на следующий месяц, а прижимают к последнему дню.

**Следствие:** задача, закрытая с опозданием, получает следующую дату тоже в
прошлом и сразу попадает в просроченные. Ежедневная с `📅 2026-08-01`, закрытая
20 августа, получит `📅 2026-08-02`. Это ожидаемое поведение, догонять до
сегодняшнего дня не нужно.

### Выполнение и генерация повтора

Единственная автоматика в файле - **переключение чекбокса**. Определяется
сравнением состояния чекбоксов блока до и после; предыдущее состояние хранит
карта.

| Переход | Действие |
|---|---|
| не все отмечены -> все отмечены | поставить `✅ <сегодня>`; есть 🔁 - сгенерировать новый блок и удалить 🔁 из текущего |
| все отмечены -> не все отмечены | убрать ✅ |
| любое другое изменение (текст, параметры, чекбоксы без смены итога) | только обновить карту, файл не править |

- **Триггер один и тот же**, откуда бы галку ни поставили: из карточки календаря
  или руками в файле. Обе дороги сходятся в `syncContent`.
- **Отметка на расчётном дне череды выполняет только этот день.** Карта получает
  день карточки третьим аргументом `toggleCheckbox`; отличается он от даты показа
  блока - **этому дню заводится свой блок**: 📅 этого дня, чистое тело со снятыми
  галочками, без 🔁. Текущий блок остаётся как был, со своим днём и своим
  повтором. Когда череда дойдёт до отмеченного дня, она его **перескочит**
  (`nextFreeDate`) - день уже занят своим блоком.
  ✅ в такой блок ставится **той же записью**, если галочка оказалась последней:
  блок только что появился, прошлого состояния у него в индексе нет, и автоматика
  переключения на него не сработает. Отметили одну подзадачу из трёх - блок дня
  просто стоит невыполненным, дальше он закрывается как обычная задача.
- **Генерация повтора - одна запись в файл:** ставится `✅ <сегодня>`, из блока
  удаляется 🔁, и в том же файле вставляется новый блок: 📅 по расчёту, тот же
  🔁, то же тело со снятыми чекбоксами, без ✅.
- **Все перемены строки задачи - одной правкой** (`taskLineEdit`): ✅ и снятие 🔁
  при генерации, новая 📅, снятие ↔️ и галочки при переносе. Параметры и галочка
  задачи живут в одной строке, и две правки одной строки в `applyEdits` затёрли
  бы одна другую. Галочки подзадач снимает `clearSubtasksEdits`, строку задачи он
  не трогает.
- **Сгенерированный блок встаёт непосредственно над закрытым** - как и говорит
  спецификация. **Блок дня, отмеченного наперёд, дописывается в конец файла**
  (`blockAppendAt`): он уже выполнен, наверху ему делать нечего.
- **Уже лежащие блоки не двигаются никогда.** Ни сортировки по дате, ни
  перекладывания: сложился файл так, что выполненные оказались сверху, - там они и
  останутся. Плагин только дописывает новое.
- **День, у которого уже есть свой блок этой цепочки, череда перескакивает**
  (`nextFreeDate`). Так работает и отметка наперёд, и перенос: занятый день держит
  свой блок, и второй на нём дал бы вторую карточку. Блоки чужих задач из того же
  файла дни не занимают (`takenDays` фильтрует по `blockChain`). Свободного дня не нашлось за 500 шагов -
  генерации не будет: оборвать цепочку честнее, чем поставить второй блок на
  занятый день.
- **Новые файлы при повторе не создаются, имя файла не меняется.** Цепочка живёт в
  одном файле: сверху актуальный блок, ниже архив выполненных.
- Инвариант «в цепочке ровно один блок с 🔁» поддерживается автоматикой, но руками
  его можно нарушить. Плагин не вмешивается: каждый блок с 🔁 при своём выполнении
  сгенерирует свой следующий.
- Задача без 🔁 при выполнении просто получает ✅. Повторная генерация из закрытого
  блока невозможна - 🔁 у него уже нет, откат генерации не нужен.
- ✅ и фактическое состояние чекбоксов **могут расходиться**, если так написано
  руками. Это допустимо и не исправляется.
- **Отметки, сделанные при выключенном плагине, не догоняются:** события
  переключения не было, а при индексации автоматика не срабатывает - состояния
  блока в карте ещё нет. Такой блок остаётся невыполненным до следующего
  переключения чекбокса.

### Перенос на другой день

**Новая дата пишется в 📅, ↔️ плагин больше не ставит** (правка от 30.10.2026,
решение пользователя). Логика переноса прежняя, меняется только запись
экземпляра: вместо `📅 <день череды> ↔️ <новый день>` у него `📅 <новый день>`.

- **Блок без 🔁** - один экземпляр, у него просто меняется 📅. Был в строке ↔️ -
  уходит той же правкой (`taskLineEdit`): дата теперь одна.
- **Блок цепочки, переносят его собственный день.** В конец файла встаёт блок
  экземпляра с 📅 нового дня, тело **с уже поставленными галочками** (это тот же
  экземпляр, просто в другой день), без 🔁 (`occurrenceBlockLines` с
  `keepMarks`). Сам блок цепочки шагает на ближайший свободный день и начинает с
  чистого тела.

```
- [ ] Полить фикус 📅 2026-08-22 🔁 Каждую неделю в Субботу

перенесли на 25-е ->

- [ ] Полить фикус 📅 2026-08-29 🔁 Каждую неделю в Субботу
- [ ] Полить фикус 📅 2026-08-25
```

- **Блок цепочки, переносят расчётный день череды.** В конец файла встаёт блок
  экземпляра с 📅 нового дня и **чистым** телом - отмечать на расчётном дне было
  нечего. Блок цепочки остаётся ровно как был.

```
- [ ] Полить фикус 📅 2026-08-29 🔁 Каждую неделю в Субботу, Воскресенье

перенесли воскресенье 30-е на четверг 3-е ->

- [ ] Полить фикус 📅 2026-08-29 🔁 Каждую неделю в Субботу, Воскресенье
- [ ] Полить фикус 📅 2026-09-03
```

- **Уехавший расчётный день из череды не уходит.** Пометить его занятым было
  нечем, кроме ↔️, а его больше нет: карточка воскресенья 30-го остаётся на месте,
  и 3-е появляется рядом. Пользователь это следствие принял. Занята только новая
  дата - на ней свой блок, и череда её перескакивает.
- **Свой день череды при переносе освобождается** - но цепочка шагает дальше, и
  до него череда не возвращается: она считается вперёд от новой 📅.
- **Свободного дня череде не нашлось** (`nextFreeDate` вернул `null`) - череду не
  двигаем, но экземпляр всё равно записываем: потерять его хуже, чем оставить
  цепочку на месте.
- **Старые ↔️ в файлах читаются как раньше:** блок показывается на дне ↔️
  (`showDate`), а занятыми у него считаются оба дня (`takenDays`). ↔️ не входит в
  отпечаток блока (`blockShape`), автоматика чекбокса на таких блоках работает.
  Перенесли такой блок - ↔️ уходит, новая дата встаёт в 📅.
- **Ручная правка ↔️ и 📅** - это просто другие даты, никакой автоматики.
- **Имя файла при переносе не меняется.**
- **Кнопка переноса есть у любой карточки**, в том числе на расчётном дне череды.
  День карточки уходит в карту третьим аргументом `moveTask(key, date, from?)`,
  ровно как `showOn` у `toggleCheckbox`. Совпал с днём показа блока - уезжает сам
  блок, отличается - расчётный день череды.
- Отметить расчётный день - другое дело: там у дня появляется свой блок с 📅 этого
  дня (см. выше), а череда остаётся на месте.

## Карта задач

Источник истины - файлы. Карта ([src/taskMap.ts](../src/taskMap.ts)) - производный
индекс с API на запись.

```ts
interface Task {
	key: string;            // `${filePath}${fileName}.md#${blockIndex}`
	blockIndex: number;     // порядковый номер блока в файле, считая невалидные
	date: string;           // 📅, день задачи в череде и база повтора
	move: string | null;    // ↔️, день показа перенесённого экземпляра
	repeat: string | null;  // 🔁, текст как написан
	done: string | null;    // ✅
	fileName: string;       // без .md
	filePath: string;       // '/Календарь задач/', слеши по краям
	body: string | null;    // '- [ ] Task\n\t- [ ] Sub Task'
	checked: boolean;       // все чекбоксы отмечены, справочное поле
	sortKey: string;        // ключ сортировки, в файл не пишется
	chain: string;          // цепочка повтора: первый пункт тела, в файл не пишется
}
```

- **Даты только строками.** Смешанный `string | Date` означал бы две ветки кода на
  каждое сравнение.
- **Карта живёт в плагине**, а не в компоненте: автоматика чекбокса должна
  срабатывать и при закрытой вкладке календаря. Поднимается на
  `workspace.onLayoutReady` - до этого список файлов хранилища ещё неполный.
- **Синхронизация двусторонняя:** события `create/modify/delete/rename` обновляют
  карту, запись через API карты правит файл (`vault.process`).
- **Хранилище на запись при старте не сканируется.** Индексация только читает.
- **Защита от цикла «запись -> событие -> запись»:** хэш содержимого по пути плюс
  debounce 300 мс. После своей записи карта запоминает хэш результата, и `modify`
  от неё же упирается в этот хэш и уходит ни с чем.
- **Отпечаток блока** (`blockShape`) - **его параметры, кроме ↔️**. Автоматика
  срабатывает, только если отпечаток совпал с запомненным: номер блока сам по
  себе ненадёжен, вставили блок выше - и все номера съехали, а параметры уезжают
  вместе со своим блоком (и 📅 у блоков одной цепочки разные).
  **Тело в отпечаток не входит** (правка от 22.08.2026): дописали в закрытый блок
  снятую подзадачу - блок перестал быть отмеченным целиком, и ✅ обязано уйти.
  Пока тело считалось частью отпечатка, такая правка выглядела как «другой блок»,
  и ✅ висело на невыполненной задаче. **↔️ не входит** по той же причине: перенос
  меняет день показа, но блок остаётся тем же самым.
- **Невалидный блок автоматика не трогает** (`isValidBlock`): сняли из тела все
  чекбоксы - задача ушла с календаря, но её ✅ остаётся написанным как есть.

API на запись: `toggleCheckbox(key, index, showOn?)`, `moveTask(key, date, from?)`,
`createTask(date, text)`, `refresh()`. Все они сводят результат в карту **сразу**,
не дожидаясь события: галочку ставит текст заметки, а не браузер, и до конца
debounce карточка стояла бы в прежнем виде.

`locate(key)` - только чтение: строки блока в файле для подсветки при переходе
(см. «Управление карточкой»). Файл читается заново, номеров строк в карте нет.

## Файл задачи

**Задачи группируются по годам** (правка от 30.10.2026, с 15.10.2026 были
месячные `YYYY-MM.md`): новая задача ложится в файл `YYYY.md` в папке для новых
задач, год - по 📅 задачи, а не по дню создания (задача на 5 января 2027,
заведённая в декабре, - в `2027.md`). Файла года нет - он создаётся
(`buildTaskFile`), есть - задача дописывается **под всеми задачами** в нём, сразу
за последним блоком (`appendTaskBlock`). Прежние месячные файлы не трогаются и
читаются как прежде. Текст ниже
последнего блока остаётся ниже новой задачи. В файл без задач блок встаёт в
конец, через пустую строку от текста.

Цепочка повтора живёт в том файле, где задачу завели, и не переезжает в файлы
следующих лет. Файл начинается пустой строкой и заканчивается пустой строкой,
блоки идут подряд; у цепочки обычно **сверху актуальный, ниже архив
выполненных**.

```
                                                   <- пустая строка
- [ ] Купить молоко 📅 2026-08-21 🔁 Каждый день
- [x] Купить молоко 📅 2026-08-20 ✅ 2026-08-21
                                                   <- пустая строка
```

«Обычно» - потому что порядок складывается сам, из двух правил на вставку:

- **следующий по череде** встаёт непосредственно над закрытым блоком - цепочка
  остаётся вместе, и в чистом файле актуальный оказывается сверху;
- **день, отмеченный наперёд**, дописывается в конец (`blockAppendAt`) - он сразу
  выполнен, и место ему в архиве.

**Уже лежащие блоки плагин не двигает никогда:** ни сортировки по дате, ни
перекладывания. Сложился файл иначе - так и останется, карте порядок безразличен,
она адресует блоки номером.

**Имя файла:** `YYYY.md` (`yearFileName`). Файлы прежних видов - месячные
`YYYY-MM.md` (15.10-30.10.2026) и `YYYY-MM-DD - <текст>.md` (до 15.10.2026, одна
задача на файл) - читаются как прежде: задачей файл делает блок, а не имя.

**Имя задаётся один раз при создании и дальше не меняется:** ни при сдвиге даты
повтором, ни при правке текста, ни при выполнении. Переименование ломало бы
ссылки `[[...]]` на заметку, а дата и текст в карте берутся из содержимого блока.

## Календарь и карточки

- **Точка на дне** - есть задача с этим **днём показа** (↔️, если экземпляр
  переносили, иначе 📅) и без ✅, либо на этот день приходится **расчётный день
  череды повтора**. Прошлое и будущее не различаются.
- **Череда повтора считается вперёд от 📅** (`occurrencesInRange`) на всю
  видимую сетку. В файле живёт только текущий блок, следующий появляется после
  закрытия предыдущего, - без расчёта у повторяющейся задачи была бы одна точка.
  До 📅 череда не заглядывает: задачи тогда ещё не было. Перебор ограничен
  `OCCURRENCE_LIMIT` (500 шагов): ежедневная задача покрывает этим полтора года,
  дальше проекция молча обрывается.
- **День, у которого в этой цепочке уже есть свой блок, из расчёта выпадает** - его
  судьбу решает блок, а не череда. У перенесённого блока таких дней два: 📅, с
  которого он уехал, и ↔️, на который приехал. Тем же набором пользуется генерация,
  поэтому календарь и файл не расходятся.
- **Карточка показывает тело без параметров**: из строки задачи они вырезаются
  вместе с пробелом перед ними (`withoutParams`), текст между ними остаётся.
- **Выполненная показывается целиком, с отмеченными чекбоксами:** снятие одной
  галки - единственный способ вернуть задачу в работу.
- **Группы и порядок:** просроченные (красная рамка) -> обычные задачи
  выбранного дня -> повторяющиеся задачи дня (и свой блок цепочки, и расчётный
  день череды) -> выполненные. Разделителей нет, группы различает вид
  карточки. Обычные выше повторяющихся - правка от 30.10.2026 (`dayTasks`):
  разовое дело легко потерять среди ежедневных.
- **Особой рамки у повторяющейся задачи нет.** Жёлтая рамка `--is-repeat`
  прожила 30.10.2026 полдня и убрана по просьбе пользователя; повторяющиеся
  отличает только место в списке.
- **Признак «выполнена» для группировки - наличие ✅** (`done !== null`), а не
  `checked`: галочки могли снять руками, оставив ✅.
- **Просрочена** = день показа меньше сегодняшнего и ✅ нет. Уехавший вперёд
  экземпляр долгом быть перестаёт, уехавший назад - становится. Просроченные
  показываются в списке **любого** выбранного дня; на своём дне карточка не
  задваивается - в группу дня просроченные не попадают.
- **На расчётном дне череды тоже есть карточка**, обычная, в группе дня: её и
  отмечают, если нужно выполнить не ближайший повтор, а, скажем, следующую
  субботу. Отметка заводит блок этого дня и закрывает только его - текущий день
  череды остаётся невыполненным. Задача, уже показанная в другой группе
  (просроченная висит в списке каждого дня), расчётной карточкой не задваивается:
  один блок - одна карточка на день.

**Сортировка** (правка от 15.10.2026). Группы - просроченные, обычные задачи дня,
повторяющиеся задачи дня, выполненные, - а внутри групп так:

- **просроченные, обычные и повторяющиеся задачи дня - новое сверху**
  (`compareByNewness`), каждая группа отдельно. Времени
  создания у задачи нет, поэтому новизна - место блока: новая задача
  дописывается под все задачи своего файла, значит ниже в файле - новее. Между
  файлами сравниваются имена: у годовых файлов это год, у прежних месячных -
  месяц, `2026-09` новее `2026-08`. Годовой файл новее месячных своего года
  (`newnessName` сравнивает `2026` как `2026-13`): новые задачи пишутся туда
  после месячных, а лексически `2026` меньше `2026-10`. Дальше путь папки, затем
  `blockIndex` по убыванию;
- **выполненные - по наименованию** (`compareByName`), как и раньше.

Время создания файла (`stat.ctime`) для новизны не годится: на этом разделе
(fuseblk) `birthtime` равен `ctime`, то есть времени последней смены статуса, и
сдвигается с каждой записью - проверено 15.10.2026. Следствия выбранного правила:
следующий блок повтора встаёт на место закрытого и новизну цепочки не меняет, а
перенесённый экземпляр цепочки дописывается в конец файла и становится в нём
самым новым.

**Ключ наименования** для выполненных считается один раз при индексации, живёт в
`sortKey`, в файл не пишется. Берётся первый элемент тела, затем по шагам: снять маркер, развернуть
ссылки в текст, снять инлайн-разметку и решётку тега, снять ведущие эмодзи (до
стабилизации), снять ведущие небуквенные символы, свернуть пробелы. Пусто после
нормализации - берётся текст после снятия маркера; всё ещё пусто - карточка уходит
в конец своей группы.

Сравнение одним общим коллатором
`new Intl.Collator('ru', { numeric: true, sensitivity: 'base', ignorePunctuation: true })`:
собирать сравнитель на каждое сравнение (как делает `localeCompare` со строкой
локали) заметно дороже. Ключи второго уровня при равенстве: день
показа по возрастанию, затем имя файла, затем `blockIndex`.

**Поле создания.** Кнопка справа и Enter создают задачу **без перехода в файл**.
Кнопки «создать и открыть» больше нет (убрана 15.10.2026): новая задача и так
встаёт наверх своей группы. Плейсхолдер подставляет выбранную дату. Блок - одна
строка `- [ ] <текст из поля> 📅 <выбранная дата>` - ложится в годовой файл (см.
«Файл задачи»). Эмодзи-параметры, набранные в поле, разбираются как в файле:
`Встреча 🔁 Каждый вторник` заведёт повторяющуюся задачу, а 📅 из поля заменится
выбранной датой. Папка для новых задач читается в момент
создания, нет её - создаётся вместе с родителями.

Поле - **`textarea` с высотой под текст** (правка от 30.10.2026): длинная задача
переносится и видна целиком. Высоту ставит `fitCreateInput` на каждый `input`
(`scrollHeight` плюс рамка), после создания она сбрасывается в одну строку;
потолок - `max-height` в стилях, дальше поле прокручивается. Перевода строки в
задаче не бывает: Enter ловится на `beforeinput` (`insertLineBreak`) и создаёт
задачу, а не переносит строку. Не `keydown` - так срабатывает и «Готово» экранной
клавиатуры, а Enter, которым IME подтверждает слово (`isComposing`), задачу не
создаёт. Вставленный текст в несколько строк `createTask` склеивает пробелами.
Высота не пересчитывается при смене ширины панели - только при вводе.

**Управление карточкой.** Две кнопки: переход в файл на правку и смена даты.

**Переход подсвечивает блок задачи** (правка от 14.10.2026): карта находит строки
блока (`locate`), и они уходят в `openLinkText` как `eState`
`{ line, startLoc, endLoc }` - ровно та форма, которую `MarkdownView` сам
собирает для ссылки `[[Заметка#Заголовок]]`. В режиме правки Obsidian подсвечивает
диапазон штатной вспышкой `is-flashing`, прокручивает к нему и ставит курсор в
начало блока; в режиме чтения работает `line`. Выделения нет намеренно: с ним
первое же нажатие клавиши стёрло бы блок. Подсвечивается блок карточки, у
расчётного дня череды - блок цепочки. Строки не нашлись - файл открывается без
подсветки. `startLoc`/`endLoc` - не публичный API (сверено по `app.js` Obsidian
1.14.4), поэтому при обновлении Obsidian стоит проверить глазами.

Смену даты рисует **штатное поле `input type="date"`** (решение от 22.08.2026):
на телефоне это системный выбор во весь экран, на ПК - окно браузера у карточки.
Поле лежит в одной обёртке с кнопкой и прозрачно, но **не спрятано** -
`showPicker()` не открывает то, что не отрисовано. Долгого нажатия по карточке
нет намеренно: оно конфликтует с выделением текста и чекбоксами.

## Тело задачи: ссылки и подзадачи

Отрисовку тела делает [TaskBody.vue](../src/components/TaskBody.vue) штатным
`MarkdownRenderer.render`. Он отдаёт готовую разметку, но **ни с хранилищем, ни с
файлом её не связывает**: в режиме чтения переходы и галочки обрабатывает сама
заметка, а в чужом контейнере этим заниматься некому. Поэтому и ссылки, и чекбоксы
обработаны руками.

| Что в тексте | Что в разметке | Что делает плагин |
|---|---|---|
| `[[Заметка]]`, `[[Заметка\|подпись]]` | `a.internal-link`, цель в `data-href` | `workspace.openLinkText(href, sourcePath, Keymap.isModEvent(event))` |
| `[текст](Заметка.md)` | тоже `a.internal-link` | то же самое |
| `[текст](https://…)` | `a.external-link` | `window.open(href, '_blank')` |
| `#тег` | `a.tag` | ничего - штатного API для поиска по тегу нет |

- Цель берётся из `data-href`, а не из `href`: у неразрешённых ссылок `href` пуст.
- `event.preventDefault()` обязателен: иначе клик уйдёт по `href` и утащит за
  собой всю вкладку Obsidian.
- Средний клик приходит **auxclick'ом**, поэтому обработчик висит на обоих
  событиях; отметкой подзадачи средний клик не считается.
- **Предпросмотр по наведению** - событие `hover-link` от `mouseover`; чтобы
  core-плагин «Предпросмотр страницы» нас слушал, в `onload` зовётся
  `registerHoverLinkSource`.
- Компонент отдаёт наверх **порядковый номер** чекбокса сверху вниз, а не номер
  строки: `data-line` рендера не документирован и меняется от версии к версии.
- **Клику обязателен `preventDefault`:** галочку ставит текст заметки, а не
  браузер. Без него разметка разъедется с файлом там, где перерисовки не
  случается. Закреплено тестом «сам чекбокс компонент не переключает».

## Подводные камни

- **Пакет `obsidian` - это только `.d.ts`**, рантайма нет. В тестах он подменяется
  моком через alias в `vitest.config.mts`.
- **`moment` берётся из `obsidian`** (`import { moment } from 'obsidian'`), а не из
  зависимости. Пакет `moment` стоит только ради типов и тестов.
- **Нумерация чекбоксов считается по одному и тому же набору строк** и при показе
  (`renderLines`), и при отметке (`checkboxLines` поверх него). Разойдись отбор -
  галочка правила бы чужую строку. Отсюда же пропуск строк внутри блоков кода: их
  рендер чекбоксами не делает.
- **`tsc` не проверяет `.vue`** - в tsconfig они включены, но без `vue-tsc` это
  пустышка. Линтер тоже: `eslint` падает на `.vue`. Статическая проверка
  компонентов держится на тестах.
- **Настройки плагина - обычный объект, Vue за ним не следит.** Поэтому папку
  для новых задач читает карта в момент `createTask`, а не `computed` компонента.
  Скан от настроек не зависит, поэтому смена настройки карту не пересобирает и
  подписки на настройки нет (убрана 14.10.2026 вместе с пересбором).
- **`MarkdownRenderer.render` отдаёт голую разметку.** Вид ей придают стили режима
  чтения Obsidian, и все они начинаются с `.markdown-rendered`. Контейнеру тела
  даны оба класса - `markdown-preview-view markdown-rendered`; поля страницы,
  которые тянет за собой первый, гасятся в `styles.css` (`padding` через
  `!important` - иначе не перебить).
- **Наведение в стилях - через `@media (hover: hover) and (pointer: fine)`**, а не
  по ширине окна: на тач-экране правило по ширине срабатывает от касания и
  залипает.
- **Перемещение файла в Obsidian - это `rename`**, и обработчику приходит **старый
  путь** вторым аргументом: без него переехавшая задача висела бы в календаре
  дважды - по старому пути и по новому.
- **Подписки на события хранилища снимает `TaskMap.stop()`** из `onunload`
  плагина, а не компонент: закрытие вкладки календаря карту не гасит.

## Расчёт на большое хранилище

- **Файлы читаются группами по 20** при полном скане: по одному - долго, все
  разом - упирается в диск.
- **Хэш содержимого** отсекает повторную работу: то же содержимое -
  переиндексировать нечего.
- **Переиндексируется только тронутый файл**, полный пересбор - лишь при старте.
- **Сканируется всё хранилище**, но читаются только `.md` (`getMarkdownFiles`), а
  разбор файла без блоков задач дешёвый.
- **Плоский список задач собирается лениво** (`snapshot`), а не на каждое событие.
- **`Intl.Collator` вместо `localeCompare`** в сортировке.
- **Тело блока разбирается один раз при индексации** и лежит в `Task.body` -
  карточке дочитывать файл не нужно.

## Известные проблемы

- **Пункт без галочки задачей не бывает**, даже с 📅: отмечать в нём нечего.
- **Вложенных задач нет.** Строка с отступом всегда подзадача, её эмодзи -
  просто текст. Задача внутри чужого списка (`- Проект` и под ним
  `- [ ] Дело 📅 ...`) календарём не видна.
- **Отмеченная строка задачи при открытых подзадачах выполненной не считается**:
  ✅ ставится, только когда отмечено всё (решение от 30.10.2026).
- **Файлы с переводами строк CRLF не читаются**: `.` в регулярках чекбокса не
  берёт `\r`. Так было и в формате 3.0; Obsidian сам пишет LF.
- **Просроченные закрываются по одному дню за раз** - это следствие расчёта от
  базы: закрыл долг, получил следующую дату, тоже в прошлом.
- **Мусор, написанный руками, плагин не чинит.** Два блока с 🔁 в одной цепочке,
  ✅ при снятых галочках, дата вне череды повтора - всё это остаётся как есть.
- **Цепочка держится на тексте задачи.** Поправили его у текущего блока -
  отмеченные наперёд и перенесённые блоки с прежним текстом цепочке больше не
  принадлежат, и на их днях снова появляется расчётная карточка. Две разные
  задачи с одинаковым текстом в одном файле, наоборот, считаются одной
  цепочкой и занимают дни друг друга.

## Соглашения

- Отступы - **табы**, кавычки одинарные, точка с запятой обязательна.
- Комментарии и строки интерфейса - по-русски.
- Классы в разметке и стилях: `task__calendar-*`, модификаторы `--is-*`.
- Тесты с префиксом **ЗАФИКСИРОВАН ДЕФЕКТ** закрепляют текущее неверное
  поведение: такой тест упадёт при починке бага, это ожидаемо.
- Правки минимальные, существующие комментарии сохраняются дословно.
