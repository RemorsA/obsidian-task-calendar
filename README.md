# Task calendar

Календарь задач внутри Obsidian: сетка месяца с точками по дням и список задач
выбранного дня. Задачи живут прямо в заметках - обычными пунктами списка с эмодзи,
без базы, без служебных файлов и без своего формата поверх Markdown.

Версия 3.0. Требуется Obsidian 1.6 или новее. Работает и на телефоне.

## Как открыть

- иконка календаря на левой панели;
- `Ctrl + P` -> **Task calendar: Открыть календарь задач**.

## Настройки

| Настройка | Что делает |
|---|---|
| Папка для новых задач | Где лежат месячные файлы с задачами, созданными из календаря. `/` - корень хранилища. Нет такой папки - создаётся при первой задаче |

Задачи ищутся по всему хранилищу, во всех папках. Ни имя файла, ни папка на разбор
не влияют: задачей заметку делает валидный блок внутри неё.

## Формат задачи

Задача - **блок строк списка с эмодзи** плюс тело с отступом:

```markdown
- 📅 2026-08-21
- 🔁 Каждый день
	- [ ] Купить молоко
		- [ ] Проверить срок
```

| Параметр | Что значит | Обязателен |
|---|---|---|
| 📅 | день задачи, точка отсчёта повтора | да |
| ↔️ | день показа, если экземпляр перенесли | нет |
| 🔁 | повтор | нет |
| ✅ | отметка выполнения | нет |

**Файл - авторитет.** Любую строку параметров можно выставить, изменить или
удалить руками - плагин это подхватит. Сам он ничего не нормализует и не
переписывает: единственное, что он пишет в файл по своей инициативе, - результат
переключения чекбокса и переноса.

Правила разбора:

- **параметр - это пара «эмодзи + значение»**: `- 📅` без даты остаётся обычным
  пунктом списка;
- **порядок строк параметров любой**, плагин пишет их в порядке 📅, ↔️, 🔁, ✅;
- **дата - строго `YYYY-MM-DD`**; `21.08.2026` датой не считается;
- **тело - строки с отступом сразу под параметрами**, и в карточку из него
  попадают только списки: чекбоксы, маркированные и нумерованные пункты любой
  вложенности. Абзацы, заголовки, цитаты, таблицы и содержимое блоков кода не
  показываются;
- **задачу заканчивает любая строка без отступа**, которая не параметр: заголовок,
  абзац, обычный пункт списка. Подпункты под ней задаче уже не принадлежат, даже
  если стоят с отступом. Пустые строки задачу не заканчивают;
- **отступы** читаются любые - таб, 2 или 4 пробела, в одном файле вперемешку;
  пишутся всегда табами;
- **в одном файле блоков может быть много**, они идут подряд, без разделителей.
  Новый блок начинается со строки параметра, если такой параметр в текущем блоке
  уже есть или у текущего блока уже началось тело.

### Когда блок становится задачей

Блок попадает в календарь, только если выполнено **всё**:

1. есть 📅 с корректной датой;
2. в теле есть хотя бы один чекбокс;
3. если есть 🔁 - её текст разобрался.

Иначе блок игнорируется молча: карточки нет, файл не правится, ошибок не
показывается. Задача без единого чекбокса невидима - отмечать в ней нечего.

## Повторы

```
кажд<окончание> [<N>] <единица> [в <список>]
```

Регистр и падежи не важны, число с единицей согласовывать не обязательно: «каждые
2 дня» и «каждый 2 день» - одно и то же. Без числа `N = 1`.

| Единица | Как писать |
|---|---|
| день | день, дня, дней, дни |
| неделя | неделя, неделю, недели, недель, неделе |
| месяц | месяц, месяца, месяцев, месяцы |
| год | год, года, году, годов, годы, лет |
| дни недели | понедельник, вторник, среда/среду, четверг, пятница/пятницу, суббота/субботу, воскресенье |
| месяцы | январь/января/январе и так же остальные |

Оговорка `в <список>` уточняет **только свою единицу**: дни недели уточняют
неделю, месяцы - год. Перечислять можно через запятую или «и».

```
Каждый день
Каждые 3 дня
Каждую неделю в Понедельник, Среду
Каждый 2 месяц
Каждый год в Марте, Сентябре
```

Не принимаются (блок станет невидимым): `Каждый месяц в Субботу`,
`Каждый день в Субботу`, `Каждую неделю в Марте`.

Понимаются и короткие формы: `Ежедневно`, `Еженедельно`, `Ежемесячно`,
`Ежегодно`, `Каждую субботу` (= каждую неделю в субботу), `Каждый март`
(= каждый год в марте), `каждый 2-й день`.

### Какой день будет следующим

База - **📅 выполненного блока**, шаг применяется один раз. Ни ✅, ни сегодняшний
день в расчёте не участвуют.

| Повтор | Правило |
|---|---|
| день, N | база + N дней |
| неделя, N, без дней | база + 7×N дней |
| неделя, N, дни D | ближайший день из D после базы внутри её недели, иначе неделя базы + N недель |
| месяц, N | база + N месяцев, число сохраняется (31 -> 28/29/30) |
| год, N, без месяцев | база + N лет (29 февраля -> 28 февраля) |
| год, N, месяцы M | ближайший месяц из M после базы в том же году, иначе год базы + N |

**Следствие:** задача, закрытая с опозданием, получает следующую дату тоже в
прошлом и сразу оказывается просроченной. Ежедневная с `📅 2026-08-01`, закрытая
20 августа, получит `📅 2026-08-02`. Долги закрываются по одному дню - это
задумано, догонять до сегодня плагин не будет.

**День, у которого в этом файле уже есть свой блок, череда перескакивает.**

## Выполнение

Всё завязано на **чекбоксы тела**. Откуда поставлена галочка - из карточки
календаря или руками в заметке, - неважно.

| Что произошло | Что делает плагин |
|---|---|
| отмечены все чекбоксы блока | ставит `✅ <сегодня>`; есть 🔁 - создаёт следующий блок цепочки и убирает 🔁 из текущего |
| снята хотя бы одна галочка у закрытого блока | убирает строку ✅ |
| любая другая правка | ничего не пишет |

Следующий блок цепочки встаёт **прямо над закрытым**: 📅 по расчёту, та же строка
🔁, то же тело со снятыми галочками. Так в файле сверху оказывается актуальный
блок, а ниже - архив выполненных.

```markdown
- 📅 2026-08-21
- 🔁 Каждый день
	- [ ] Купить молоко
- 📅 2026-08-20
- ✅ 2026-08-21
	- [x] Купить молоко
```

Уже лежащие блоки плагин никогда не двигает и не сортирует.

**Отметить можно и будущий день повтора.** У повторяющейся задачи точки стоят на
всех расчётных днях, и на каждом из них есть обычная карточка. Отметка на таком
дне закрывает **только этот день**: ему заводится свой блок (в конце файла, уже с
✅), а текущий блок цепочки остаётся невыполненным. Когда череда дойдёт до этого
дня, она его перескочит.

Отметки, сделанные при выключенном плагине, не догоняются: события переключения не
было, и при следующем запуске блок останется невыполненным.

## Перенос на другой день

Кнопка с календариком на карточке открывает штатный выбор даты - на телефоне
системный, на компьютере обычное окно браузера.

- **Разовая задача** просто получает другую 📅.
- **Экземпляр повторяющейся** уезжает отдельным блоком: 📅 остаётся днём череды, с
  которого он уехал, ↔️ - день, где он теперь показывается. Уехавший день остаётся
  занятым, череда его перескакивает, а точка в календаре переезжает на новую дату.

Перенесли **день самого блока** - тело едет вместе с уже поставленными галочками,
а цепочка шагает на ближайший свободный день:

```markdown
- 📅 2026-08-22                     - 📅 2026-08-29
- 🔁 Каждую неделю в Субботу        - 🔁 Каждую неделю в Субботу
	- [ ] Полить фикус     ->       	- [ ] Полить фикус
                                    - 📅 2026-08-22
                                    - ↔️ 2026-08-25
                                    	- [ ] Полить фикус
```

Перенесли **расчётный день череды** - уезжает только он, цепочка остаётся на месте:

```markdown
- 📅 2026-08-29                              - 📅 2026-08-29
- 🔁 Каждую неделю в Субботу, Воскресенье    - 🔁 Каждую неделю в Субботу, Воскресенье
	- [ ] Полить фикус              ->       	- [ ] Полить фикус
                                             - 📅 2026-08-30
                                             - ↔️ 2026-09-03
                                             	- [ ] Полить фикус
```

Суббота осталась при своём блоке, воскресенье показывается 3 сентября, череда
продолжается 5 и 6 сентября.

Правка 📅 и ↔️ руками работает так же - это просто другие даты. Имя файла при
переносе не меняется: дата в имени это дата создания, а не источник истины.

## Календарь

- **Точка на дне** - есть невыполненная задача с этим днём показа либо на этот
  день приходится расчётный день повтора. Прошлое и будущее не различаются.
- **Порядок карточек:** просроченные (красная рамка) -> задачи выбранного дня ->
  выполненные (перечёркнутые). Просроченные и задачи дня идут **от новых к
  старым**: новее та, что ниже в своём месячном файле, а между файлами - та, у
  которой месяц позже. Выполненные - по наименованию.
- **Просрочена** - день показа в прошлом и ✅ нет. Просроченные видны в списке
  любого выбранного дня, чтобы о долге не забыть.
- **Выполненная карточка показывается целиком, с галочками.** Снять галочку -
  единственный способ вернуть задачу в работу.
- **Карточка показывает только тело**, строки параметров в неё не попадают.
- **В теле карточки работают ссылки** `[[Заметка]]` и внешние, а также
  предпросмотр заметки по наведению. `Ctrl`-клик и клик средней кнопкой открывают
  ссылку в новой вкладке.
- **Галочки в карточке отмечаются прямо там** - плагин правит текст заметки.
- **Кнопка со ссылкой** открывает файл задачи на правку и подсвечивает блок
  именно этой задачи - так же, как Obsidian подсвечивает цель ссылки на заголовок.
  Курсор встаёт в начало блока, выделения нет.
- **Поле внизу создаёт задачу** на выбранный день - кнопкой справа или `Enter`,
  без перехода в файл. Новая задача сразу встаёт наверх списка дня.

**Задачи складываются по месяцам.** Новая задача ложится в файл `YYYY-MM.md` в
папке для новых задач, месяц - по дате задачи: задача на 5 ноября попадёт в
`2026-11.md`, даже если её завели в октябре. Файла месяца ещё нет - он
создаётся, есть - задача дописывается в него под всеми задачами.

```markdown
- 📅 2026-10-15
	- [ ] Купить молоко
- 📅 2026-10-20
- 🔁 Каждую неделю во вторник
	- [ ] Полить фикус
- 📅 2026-10-16
	- [ ] Позвонить Тане
```

Повторяющаяся задача так и живёт в файле того месяца, где её завели: следующие
блоки цепочки встают рядом с ней, а не в файлы следующих месяцев. Блоки одной
цепочки плагин узнаёт по первому пункту тела, поэтому задачи по соседству друг
другу не мешают. Файлы старого вида `YYYY-MM-DD - <текст>.md` продолжают
работать.

## Чего плагин не делает

- не переносит задачи из формата версии 2.x (заметки со свойствами в YAML) -
  миграции нет, старые заметки просто не подхватываются;
- не чинит то, что написано руками: два блока с 🔁 в одной цепочке, ✅ при снятых
  галочках, дата вне череды повтора - всё это остаётся как есть;
- не переименовывает и не создаёт файлы при повторе: вся цепочка живёт в одном
  файле;
- не догоняет пропущенные повторы до сегодняшнего дня.

## Разработка

Vue 3 + TypeScript, сборка esbuild в один `main.js`, тесты на vitest.

```bash
npm install --legacy-peer-deps   # флаг обязателен: конфликт peer-зависимостей vite и vitest
npm test                         # 265 тестов
npm run typecheck                # tsc -noEmit
npm run dev                      # watch-сборка main.js на месте
npm run build                    # typecheck + прод-сборка в dist/
```

Нужен Node 18 (из-за него vite остаётся на 5, а vitest на 2). Чтобы правки увидел Obsidian, нужен `npm run dev` или `build` с
копированием `dist/main.js` в корень плагина: Obsidian грузит собранный `main.js`,
а не исходники.

| Файл | Что внутри |
|---|---|
| `src/TaskCalendarPlugin.ts` | класс плагина: карта, view, команда, настройки |
| `src/taskFormat.ts` | формат целиком: разбор блоков, грамматика повтора, расчёт дат, правки файла |
| `src/taskMap.ts` | индекс над файлами и API на запись, автоматика чекбокса |
| `src/components/TaskCalendar.vue` | сетка, точки, список карточек, создание задачи |
| `src/components/TaskBody.vue` | рендер тела задачи, ссылки и чекбоксы |
| `test/` | 265 тестов, подробности - в `test/README.md` |
